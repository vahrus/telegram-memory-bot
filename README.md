# Telegram Memory Bot

Учебный Telegram-бот с комбинированной AI-памятью. Он ведёт связный диалог за счёт короткой истории сообщений и отвечает по загруженным документам за счёт долгой памяти на embeddings и ChromaDB.

Проект показывает, как короткая и долгая память работают по отдельности и вместе. Бот запускается локально, ключи читаются из `.env`, а база документов хранится на диске.


## Возможности

- короткая память: последние 10 сообщений диалога отдельно для каждого Telegram-пользователя;
- долгая память: семантический поиск по загруженным документам;
- загрузка PDF, DOCX и TXT;
- семантический поиск через embeddings OpenAI и локальную ChromaDB;
- интерфейс в Telegram на aiogram 3.x;
- ответы через OpenAI API, модель чата задаётся в `.env`.


## Как устроена память

### Короткая память

Бот хранит последние 10 сообщений отдельно для каждого Telegram-пользователя.

Используется:

`defaultdict` + `deque(maxlen=10)`

Каждое сообщение сохраняется в виде `{"role": "user" | "assistant", "content": "..."}`. В лимит входят и реплики пользователя, и ответы бота. Память одного `user_id` не смешивается с памятью другого.

Память хранится в RAM.

После перезапуска приложения короткая память очищается. Команда `/reset` тоже очищает только её и не удаляет загруженные документы.

Текущий вопрос не записывается в историю до обращения к модели. В запрос попадают уже сохранённые сообщения и один раз текущий вопрос. После успешной отправки ответа в память попадают и вопрос, и ответ.

### Долгая память

Пользователь отправляет PDF, DOCX или TXT. Бот извлекает текст, разбивает его на фрагменты примерно по 800 символов с перекрытием около 100 символов и создаёт embeddings через OpenAI. Модель embeddings берётся из `EMBED_MODEL`, по умолчанию `text-embedding-3-small`.

Embeddings и исходные chunks сохраняются в ChromaDB. У каждого фрагмента есть metadata: `user_id`, `document_id`, `file_name`, `chunk_index`. Поиск всегда фильтруется по `user_id`, поэтому документы разных пользователей не смешиваются.

ChromaDB хранится на диске в `./memory`, поэтому данные сохраняются после перезапуска приложения. Сами файлы лежат в `./uploads/<user_id>/`.

Если документов ещё нет или поиск ничего не нашёл, бот не падает и отвечает как обычный помощник с короткой памятью.


## Логика работы

```text
Пользователь
    ↓
Telegram / aiogram
    ↓
Вопрос
    ↓
Короткая память (10 сообщений)
    +
Поиск в ChromaDB
    ↓
Релевантные фрагменты документа
    ↓
OpenAI
    ↓
Ответ пользователю
```

На каждый текстовый вопрос бот:

1. берёт уже сохранённую короткую историю пользователя;
2. создаёт embedding текущего вопроса;
3. ищет до 5 ближайших фрагментов в ChromaDB только этого `user_id`;
4. отправляет в OpenAI системную инструкцию, короткую историю, найденный контекст и текущий вопрос;
5. отправляет ответ в Telegram;
6. сохраняет вопрос и ответ в короткую память.


## Работа с документами

```text
PDF/DOCX/TXT
→ извлечение текста
→ chunks
→ embeddings
→ ChromaDB
→ semantic search
→ context
→ LLM answer
```

- PDF читается через `pypdf`;
- DOCX читается через `python-docx`;
- TXT читается как UTF-8;
- старый формат DOC не поддерживается;
- пустой документ и неподдерживаемый формат получают понятное сообщение без traceback;
- после индексации бот пишет, сколько фрагментов создано.

## Структура проекта

```text
telegram-memory-bot/
├── bot.py
├── config.py
├── short_memory.py
├── document_memory.py
├── ai_client.py
├── requirements.txt
├── .env.example
├── .gitignore
├── README.md
├── memory/
│   └── .gitkeep

    └── .gitkeep
```

- `bot.py` — команды, загрузка документов и ответы на вопросы;
- `config.py` — пути, `.env` и проверка обязательных переменных;
- `short_memory.py` — короткая память в RAM;
- `document_memory.py` — чтение файлов, нарезка текста и ChromaDB;
- `ai_client.py` — один клиент OpenAI, embeddings и сборка запроса к модели.


## Установка

Команды для macOS и Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Нужен Python 3.11 или новее.


## Настройка

Скопируйте пример окружения и заполните свои значения:

```bash
cp .env.example .env
```

В `.env` нужно указать:

| Переменная | Назначение |
|---|---|
| `BOT_TOKEN` | токен Telegram-бота от BotFather, обязателен |
| `OPENAI_API_KEY` | ключ OpenAI, обязателен |
| `CHAT_MODEL` | модель для ответов, по умолчанию `gpt-5-mini` |
| `EMBED_MODEL` | модель embeddings, по умолчанию `text-embedding-3-small` |

Пример без настоящих ключей лежит в `.env.example`. Если `CHAT_MODEL` или `EMBED_MODEL` пустые, бот подставляет значения по умолчанию. Без `BOT_TOKEN` или `OPENAI_API_KEY` бот не запускается и пишет, каких переменных не хватает. Сами ключи в лог не попадают.


## Запуск

Из корня проекта, с активированным виртуальным окружением:

```bash
python bot.py
```

Каталоги `memory` и `uploads` создаются автоматически, если их ещё нет. Остановить бота можно сочетанием Ctrl+C.


## Команды Telegram

- `/start` — приветствие и краткое описание памяти;
- `/help` — как устроена короткая память, как загрузить документ и как задавать вопросы;
- `/reset` — очистить только короткую историю текущего диалога. Документы в ChromaDB остаются.


## Проверка короткой памяти

Пример:

Пользователь:
Меня зовут Алексей.

Бот:
Приятно познакомиться, Алексей.

Пользователь:
Как меня зовут?

Ожидаемый результат:
бот отвечает, что пользователя зовут Алексей.

Документ для этого теста загружать не нужно. После `/reset` или перезапуска бота имя из короткой памяти пропадёт.


## Проверка долгой памяти

Пример:

1. загрузить `company.txt`;
2. дождаться сообщения об индексации;
3. задать вопрос по содержимому документа;
4. убедиться, что ответ основан на документе.

Если в документе нет нужного факта, бот должен прямо сказать, что не нашёл ответ в загруженных документах, а не выдумывать его.


## Проверка комбинированной памяти

Пример:

1. загрузить документ;
2. спросить: «Какие услуги предоставляет компания?»;
3. получить ответ;
4. спросить: «Какой вопрос я задавал перед этим?»;
5. бот должен использовать короткую память и назвать предыдущий вопрос.

Первый ответ опирается на долгую память, второй — на короткую историю того же диалога.


## Что хранится где

| Память | Где хранится | Что хранится | После перезапуска |
|---|---|---|---|
| Короткая память | RAM | последние 10 сообщений | очищается после restart |
| Долгая память | ChromaDB | данные документов | сохраняется после restart |


## Безопасность

API-ключи находятся в `.env`. Файл `.env` исключён из Git через `.gitignore`, в репозиторий попадает только `.env.example` с пустыми примерами. Токен бота и ключ OpenAI не записаны в исходниках и не выводятся в лог.

Каталоги `uploads/` и `memory/` тоже исключены из Git, кроме служебных `.gitkeep`. В репозиторий не попадают загруженные документы и локальная база ChromaDB.


## Итог

В проекте реализована комбинированная память AI-ассистента. Короткая память обеспечивает связность диалога, а долгая позволяет использовать загруженные документы как базу знаний.
